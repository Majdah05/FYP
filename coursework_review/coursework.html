Topic 1 — Federated Learning Fundamentals

What Is Federated Learning?

Traditional ML requires all data centralised on one server. FL inverts this: the model travels to the data, not the other way around. Each client trains a local copy of the global model on its private data, then sends only the updated weights back to a central server, which aggregates them and broadcasts a new global model for the next round.

Three motivations drive FL: Privacy (raw data never leaves the device), Communication efficiency (weights are smaller than datasets), Regulatory compliance (GDPR, HIPAA restrict data movement).

Topic 4 — Local Training, Global Rounds, and Aggregation

One Communication Round

  1. Server broadcasts: global_state = copy.deepcopy(global_model.state_dict()) — all selected clients receive identical weights.
  2. Clients train locally: config.local_epochs (default 2) epochs over private data with SGD(lr=0.01).
  3. Clients return: updated state_dict + num_samples.
  4. Server aggregates: fedavg_aggregate(updated_states, sample_counts).
  5. Server evaluates: evaluate_model(global_model, val_loader) — centralised val set, no updates.

Effective Training Budget (default config)

batches_per_client = ceil(17,999 / 64) ≈ 282 steps_per_round = 5 clients × 2 epochs × 282 batches = 2,820 total_steps_20_rounds = 56,400

Topic 5 — FedAvg Mathematics

Algorithm (McMahan et al., 2017)

w^{t+1} = Σ_k (n_k / N) · w_k^{t+1} w_k^{t+1} = weights of client k after local training in round t n_k = number of training samples on client k N = Σ_k n_k (total participating samples) w^{t+1} = new global model weights

Numerical Example

Three clients: n₁=100, n₂=200, n₃=150 → N=450. Single weight: w₁=1.0, w₂=3.0, w₃=2.0:

w_global = (100/450)×1.0 + (200/450)×3.0 + (150/450)×2.0 = 0.222 + 1.333 + 0.667 = 2.222

if tensors[0].is_floating_point():

Topic 6 — IID vs Non-IID and Dirichlet Partitioning

Why Distribution Matters

Under IID, each client's local gradient is an unbiased estimate of the global gradient — FedAvg converges well. Under non-IID, gradients point in different directions; averaging them yields a direction that may not minimise any client's loss. This is the central challenge of heterogeneous FL.

Dirichlet(α=0.1): extreme skew — one client gets ~90% of each class Dirichlet(α=0.5): significant skew (your default) Dirichlet(α=1.0): moderate imbalance Dirichlet(α=10.0): near-uniform (≈ IID)

Practical Consequences

  • A client with 95% "Adipose" images fine-tunes well for that class but degrades on others.
  • After aggregation, biases partially cancel — but not fully.
  • More local epochs (E) amplify drift because clients train further from the global optimum.

Topic 7 — Accuracy, Loss, Convergence, and Evaluation

Metrics in evaluation.py:compute_metrics()

  • Accuracy: fraction correctly classified.
  • Macro F1: unweighted mean of per-class F1 — treats all 9 classes equally regardless of size.
  • Precision / Recall: macro-averaged.
  • AUROC: Area Under ROC (multi-class OvR, macro).

Why Macro F1 Matters

PathMNIST has class imbalance. A model that always predicts the most common class achieves ~30% accuracy but Macro F1 ≈ 0. Always report both.

Evaluation Is Centralised — No Leakage

Validation is done on the full global val_loader, never partitioned. This gives an unbiased view of global model quality. ✓

Topic 9 — Privacy, Secure Aggregation, and Homomorphic Encryption

Privacy Threats

Sending weights instead of data gives some privacy, but weights can still leak via:

  • Gradient inversion attacks: reconstruct training images from gradients.
  • Membership inference: determine if a specific sample was used.

Your current implementation has no privacy mechanism.

Differential Privacy

w_k += N(0, σ²·C²·I) before uploading C = gradient clipping bound, σ = noise multiplier Privacy budget tracked with (ε, δ)-DP

Secure Aggregation

Clients encrypt weights using pairwise masks that cancel during aggregation. The server sees only the sum — never individual updates. Library: PySyft, FATE.

Homomorphic Encryption (HE)

Server computes weighted sums on encrypted weights. Computationally expensive (10–1000× slower). Libraries: TenSEAL, SEAL.

Review Questions

  1. Why does more DP noise (larger σ) reduce accuracy?
  2. What trust assumptions can you relax in a real multi-party deployment vs. your simulation?
  3. What is the privacy advantage of secure aggregation over plain weight sharing?
