🔴 Bug 1 — Duplicate Removal Doesn't Fix client_indices

CRITICALpartition.pyLines 69–83non_iid only

Description

When Dirichlet sampling assigns the same index to multiple clients, the fallback deduplication code (lines 69–83) builds a flat unique_items list — but never writes it back into client_indices. Duplicates persist in the returned partitions.

Consequences

  • The same training sample is used by multiple clients in the same round.
  • FedAvg over-weights duplicated samples, biasing the global model.
  • Training loss appears lower than true loss (inflated by repeated samples).
  • Non-reproducible: which clients hold duplicates varies with seed.

Buggy Code

# partition.py lines 69-83 — BUGGY
flattened = [item for sub in client_indices for item in sub]
if len(set(flattened)) != len(flattened):
    seen = set()
    unique_items = []            # ← computed correctly...
    for item in flattened:
        if item not in seen:
            seen.add(item)
            unique_items.append(item)
    # ← ...but unique_items is NEVER used to update client_indices!
    missing = sorted(set(range(total_samples)) - set(unique_items))
    client_sizes = [len(items) for items in client_indices]  # still has duplicates
    while missing:
        target = int(np.argmin(client_sizes))
        client_indices[target].append(missing.pop(0))
        client_sizes[target] += 1
# Returns client_indices still containing duplicates ↑

Fix

# partition.py — FIXED dedup block
flattened = [item for sub in client_indices for item in sub]
if len(set(flattened)) != len(flattened):
    # Step 1: remove duplicates in-place, keeping first occurrence
    seen = set()
    for sub in client_indices:
        keep = []
        for item in sub:
            if item not in seen:
                seen.add(item)
                keep.append(item)
        sub.clear()
        sub.extend(keep)
    # Step 2: distribute any indices that were completely lost
    missing = sorted(set(range(total_samples)) - seen)
    client_sizes = [len(c) for c in client_indices]
    for idx in missing:
        target = int(np.argmin(client_sizes))
        client_indices[target].append(idx)
        client_sizes[target] += 1

Verification Test

from federated_learning.datasets.partition import partition_dataset
import numpy as np

labels = np.array([0]*10 + [1]*2 + [2]*2)   # very skewed, triggers fallback

                               distribution='non_iid',
                               dirichlet_alpha=0.01, seed=1)
all_idx = [i for client in partitions for i in client]
assert len(all_idx) == len(set(all_idx)), "DUPLICATES FOUND"
assert len(all_idx) == len(labels), "SAMPLES MISSING"
print("OK — no duplicates, no missing samples")

🟠 Bug 3 — Missing Normalisation Transform

MAJORpathmnist_loader.pyLines 17–19
# BUGGY
transform = transforms.Compose([
    transforms.ToTensor(),   # float32 [0.0, 1.0], mean ≈ 0.74, std ≈ 0.18
    # Missing: Normalize
])

Consequence

Without normalisation, CNN input activations are biased (~0.74 mean) instead of zero-centered. This slows convergence, makes results incomparable to papers that do normalise, and increases sensitivity to learning rate choice.

Fix

# FIXED — pathmnist_loader.py
transform = transforms.Compose([
    transforms.ToTensor(),
    transforms.Normalize(
        mean=[0.741, 0.533, 0.706],
        std= [0.175, 0.204, 0.168]
    )
])
# Apply this same transform to train, val, and test splits.
# Stats were computed from the train set only — no val/test leakage.

🔵 Info — Per-Round Client Selection Seeding

INFOserver.pyLine 107
# server.py line 107
selected_clients = select_clients(..., seed=config.seed + round_idx)

Using seed + round_idx ensures each round deterministically selects a different client subset. This is a valid design choice — it prevents the same clients from always being selected, which would bias the global model. Add a comment to document the intent.
