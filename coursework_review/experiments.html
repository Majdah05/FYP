Experiment 3 — Effect of Number of Clients (K sweep)

python main.py --num_clients 2  --distribution iid
python main.py --num_clients 5  --distribution iid
python main.py --num_clients 10 --distribution iid
python main.py --num_clients 20 --distribution iid

Expected Insight

More clients → smaller per-client datasets → noisier local updates → slightly slower convergence, but similar final accuracy under IID. Under non-IID, more clients amplifies heterogeneity. Measure: rounds to reach 75% validation accuracy.

Experiment 4 — Effect of Local Epochs (Client Drift Demo)

# IID — more epochs should help
python main.py --local_epochs 1 --distribution iid
python main.py --local_epochs 5 --distribution iid

# Non-IID — more epochs causes drift
python main.py --local_epochs 1 --distribution non_iid --dirichlet_alpha 0.5
python main.py --local_epochs 5 --distribution non_iid --dirichlet_alpha 0.5
python main.py --local_epochs 10 --distribution non_iid --dirichlet_alpha 0.5

Expected Insight

This directly demonstrates client drift — a core FL research finding. Non-IID accuracy should drop significantly as E increases, while IID accuracy stays stable or improves. This experiment motivates FedProx and SCAFFOLD.

Experiment 5 — Partial Client Participation (C fraction sweep)

python main.py --client_fraction 1.0 --num_clients 10
python main.py --client_fraction 0.6 --num_clients 10
python main.py --client_fraction 0.4 --num_clients 10
python main.py --client_fraction 0.2 --num_clients 10

Lower participation increases convergence variance but reduces per-round communication cost. There is typically a sweet spot around C=0.3–0.5 for large client pools.

Experiment 6 — SGD vs Adam Optimiser

python main.py --optimizer sgd  --lr 0.01
python main.py --optimizer adam --lr 0.001   # Adam uses lower lr

Adam often converges faster per round but may show higher variance across rounds in FL. SGD with momentum is the standard choice in FL research. This experiment motivates that convention.

Experiment 7 — Fixed Budget: Rounds × Local Epochs = 40

python main.py --rounds 40 --local_epochs 1    # 40 rounds, 1 epoch
python main.py --rounds 20 --local_epochs 2    # 20 rounds, 2 epochs (default)
python main.py --rounds 10 --local_epochs 4    # 10 rounds, 4 epochs
python main.py --rounds 5  --local_epochs 8    #  5 rounds, 8 epochs

Under IID, more rounds + fewer local epochs gives slightly better accuracy at 8× communication cost. Under non-IID, high-E configs diverge. This is the fundamental FedAvg communication trade-off.

Experiment 8 — Implement and Compare FedProx ⭐ Most Publishable

Motivation

FedProx (Li et al., 2020) adds a proximal term to each client's loss to prevent excessive client drift:

L_FedProx(w) = L(w) + (μ/2) · ‖w - w_global‖²

Implementation (modify client.py)

# In FederatedClient.local_train(), add global_params argument:
proximal_term = sum(
    (w - w_g).norm() ** 2
    for w, w_g in zip(self.model.parameters(), global_params)
)
loss = loss + (mu / 2) * proximal_term

Suggested Comparison

Compare FedAvg vs FedProx(μ=0.001, 0.01, 0.1) on non-IID PathMNIST with α=0.1 and E=5. FedProx should significantly outperform vanilla FedAvg. A clean comparison on PathMNIST is a valid research contribution.
