Federated Learning Baseline with FedAvg

This project implements a reproducible federated learning framework in Python using PyTorch. The baseline focuses on Federated Averaging (FedAvg), centralized training as a comparison point, and a modular dataset interface for future IDS integration.

Installation

python -m pip install -r requirements.txt

Running a smoke test

python main.py --dataset pathmnist --smoke_test --num_clients 3 --rounds 1 --local_epochs 1 --batch_size 32 --lr 0.01

Centralized training

python main.py --dataset pathmnist --num_clients 5 --rounds 5 --local_epochs 2 --batch_size 64 --lr 0.01 --distribution iid --model cnn

Federated training

python main.py --dataset pathmnist --num_clients 5 --rounds 20 --local_epochs 2 --batch_size 64 --lr 0.01 --distribution iid
python main.py --dataset pathmnist --num_clients 10 --rounds 50 --local_epochs 5 --batch_size 32 --lr 0.001 --distribution non_iid --dirichlet_alpha 0.5

FedAvg flow

The server selects participating clients, sends the current global model, clients train locally, and the server aggregates the model updates with sample-size weighting.

Aggregation formula:

w_{t+1} = sum_{k in S_t} (n_k / sum_{j in S_t} n_j) * w_{t+1}^{k}

This implementation is in federated_learning/federated/aggregation.py.

IID and non-IID partitioning

  • IID: random shuffling and splitting of the dataset.
  • non-IID: Dirichlet allocation over label distributions to create heterogeneous client data.

Outputs and plots

Every experiment writes output into a unique folder under results/ containing the config, metrics CSV, JSON logs, plot files, and checkpoints.

IDS integration

The interface in federated_learning/datasets/ids_loader.py is designed for later use with a real IDS dataset. The dataset schema must be supplied by the user: target column, numeric features, categorical features, and preprocessing strategy. The federated algorithm itself stays separate from IDS-specific preprocessing.

Future security mechanisms

This baseline intentionally omits security. The architecture is prepared for secure aggregation, differential privacy, gradient clipping, robust aggregation, and poisoning simulations by isolating aggregation logic and client update handling in dedicated modules.
